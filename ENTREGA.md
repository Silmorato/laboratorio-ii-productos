# Guía del documento y la exposición

## Documento Word (2 a 4 páginas)
- Curso, integrantes, fecha y enlace al repositorio.
- Expliquen brevemente qué hace la aplicación y qué agregaron.
- Expliquen las funciones de Application, Controller, Producto, pom.xml y application.properties.
- Describan el recorrido del stock: formulario → JavaScript → JSON → controller → modelo/lista → JSON de respuesta → pantalla.
- Incluyan una tabla de pruebas: datos enviados, estado esperado, estado obtenido y resultado. Registren stock 5, 0, -1 y ausente; nombre vacío y precio negativo.
- Incluyan capturas legibles de un POST exitoso, un error 400 y un GET con el nuevo campo.
- Expliquen qué ocurre al reiniciar y qué diferencia hay entre Git, GitHub, commit y push.
- Indiquen el aporte de cada integrante, una dificultad y cómo la resolvieron. Citen las fuentes consultadas.

## Exposición (5 a 7 minutos)
1. Ejecutar y mostrar el proyecto.
2. Crear un producto con stock y verificarlo con GET.
3. Provocar un 400 y explicar por qué sucede.
4. Mostrar los cambios en frontend y backend.
5. Explicar el recorrido de los datos y el uso de Git/GitHub.

Todos participan. La docente puede pedir que señalen una línea, predigan una respuesta o expliquen una decisión.

## Criterios de evaluación (10 puntos)
| Criterio | Puntos |
|---|---:|
| Integración del nuevo dato en formulario, JSON, backend y tabla | 3 |
| Validaciones del backend y evidencias de pruebas | 2 |
| Comprensión y explicación individual durante la exposición | 3 |
| Repositorio, commits, documento y fuentes | 2 |

El funcionamiento debe acompañarse de una explicación propia. La ampliación es opcional y no reemplaza los requisitos obligatorios.
